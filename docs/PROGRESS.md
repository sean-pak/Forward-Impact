## Phase 7: Structured form (done)
- Shipped: `/submit/[token]` (one box per known program, pre-filled from its last confirmed cycle: prison, yard, sessions, hours per participant, completion rule, registry answers; dates and counts are never pre-filled; 3 blank "another program" boxes; prison field is a searchable list of 31 names plus aliases; "about" tick boxes set the `_approx` flags) and `/submit/[token]/[id]` (confirm screen). Pure checks in `packages/shared/src/formCycle.ts`; DB work in `apps/worker/src/form/`.
- Flow: submit writes a `submissions` row (`channel = form`), draft cycles and `field_issues`; nothing counts yet. Missing enrolled / prison / start date, an unreadable value, an unmatched prison, completed > enrolled, or end < start blocks confirmation (submission `needs_info`, cycle `draft`): the CBO goes back and resubmits. A missing completion rule is flagged but not blocking and is stored as `unstated`. Confirm sets cycles `confirmed`, marks an earlier confirmed cycle with the same `cycle_key` `superseded`, and applies a stated completion rule to the program.
- Decisions: a row with no dates or counts is treated as a skipped pre-filled program. The completion rule is staged in the cycle's `extra._completion_rule` and only written to `programs` on confirm, so an unconfirmed submission cannot change confirmed numbers. The rule lives on the program, so a changed rule applies to that program's earlier confirmed cycles too. Form routes trust the unguessable `form_token` (the page is public, not behind the admin password); the web app reaches the Worker with the bearer secret.
